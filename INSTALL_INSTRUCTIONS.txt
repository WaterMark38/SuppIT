SuppIT — Lecturer login and Super Admin update
==============================================

This is a PATCH for the CURRENT SuppIT Next.js project. It is not a full project.
It keeps your existing company, customer records, quotations, invoices,
Neon database credentials and old migration files intact.

RESULT
- Existing owner is promoted to SuperAdmin; email is preserved.
- Lecturer logs in with only a username (default: administrator) and a password.
- No email is required or displayed for lecturer/Staff account creation.
- SuperAdmin may create Admin/Staff, reset Admin/Staff passwords and access all functions.
- Admin (lecturer) may create Staff and reset Staff passwords, but may not alter
  the SuperAdmin or another Admin account. The SuperAdmin is hidden from the
  lecturer's user list as well.
- Staff cannot manage other accounts.
- Business API endpoints continue to accept SuperAdmin permissions.
- Passwords remain bcrypt-hashed in Neon; none are hardcoded or included in ZIP.

IMPORTANT: The password example already shared in chat is exposed; create a
DIFFERENT private lecturer password of at least 12 characters. Share only with
the lecturer through a private channel, not GitHub or public README files.

INSTALL ON WINDOWS / WEBSTORM
1. Stop npm run dev (Ctrl+C). Ensure you are inside your SuppIT `code` folder.
2. BACK UP the code folder and your Neon development branch before changing anything.
3. Extract the contents of this ZIP into the existing `code` folder, preserving
   directory layout, replacing only the matching source files. Do not overwrite
   the full project, .env, prisma/migrations, package.json or Docker files.
4. Confirm .env points to the intended `Suppit-development` Neon branch.
5. Validate and migrate the schema:
      npm run db:validate
      npm run db:migrate -- --name superadmin_lecturer_username_only
      npm run db:generate
   STOP if Prisma asks to reset a database or warns of destructive data loss.
6. Run this ONCE to promote your existing owner and create the lecturer:
      node scripts/setup-lecturer.mjs
   Supply your current owner EMAIL and CURRENT password to verify your account.
   Set your Super Admin username (suggested: superadmin), enter an OPTIONAL
   new Super Admin password (recommended because old one was shared),
   lecturer username (suggested: administrator), and a NEW private password for lecturer.
   The lecturer has NO email address stored in Neon.
7. Start local application:
      npm run dev
   Login with usernames and passwords at http://localhost:3000 .
8. Verify protected operations: a lecturer Admin can reset Staff passwords, but
   cannot reset or rename the SuperAdmin or create Admin roles (API must return 403).
9. Run `npm run build` and `npm audit`; resolve outstanding failures before deployment.

Security notes
- Password input is visible in the terminal; no screenshots during account setup.
- Do NOT run `npm run admin:create` again; that would create a new company.
- Do NOT commit private .env files or passwords to GitHub.
- This ZIP does not directly change your Neon database; YOU apply the reviewed migration.
- If you already created username `administrator`, the script deliberately fails
  rather than overwriting its password. Use the existing SuperAdmin user management
  interface to manage it, or review conflicting accounts before trying again.
- A role-based backend check protects the SuperAdmin even from direct API calls.

Unverified: this update was inspected and syntax checked here, but was not
